# Gemini 3.7 Flash 換裝實測（主推理層）

> 2026-08-23。方法論沿用 [2026-08-02 的 model 分層實測](2026-08-02-model-tiering-ab.md)；
> 跑法與判讀紀律見 [judge-discipline](../operations/judge-discipline.md) §換 model 的量測。

## 結論

`decomposer` / `analyst-tier1` / `analyst-tier2` / `synthesizer` / `editor` / `viewpoints-debate`
六個從 `gemini-3.5-flash` 換到 `gemini-3.7-flash`。

**理由不是 3.7 比較好，是品質量不出差異而折扣期內便宜一半。** 三個 judge 與
`narrative-writer`、`podcast-writer` 不動，理由寫在 `resolve.ts` 的註解裡。

## 價格（2026-08-23 實查 ai.google.dev/gemini-api/docs/pricing）

| model | input | output | 備註 |
|---|---|---|---|
| `gemini-3.5-flash` | $1.50 | $9.00 | 現況 |
| `gemini-3.7-flash` | **$0.75** | **$3.75** | introductory，**2026-12-31 到期**，之後 $1.50 / $7.50 |
| `gemini-3.6-flash` | $0.75 | $3.75 | 同上；**與 2026-08-02 記錄的 $1.50 / $7.50 不同** |

★ 3.6 的價格變動使 [2026-08-02 對它的 NO-GO 判定失效](2026-08-02-model-tiering-ab.md)——
那次算出「只省 3.2%、年省 $0.21」的前提是它與 3.5-flash input 同價。
`pricing.ts` 的 3.6 entry 同日更正，並加了 `PRICE_EXPIRY` time-bomb：
**過時的價格 entry 比缺 entry 更難發現**，缺的會 warn，過時的只會靜靜算出錯的成本。

## 量測一：成本與 token（`pnpm model:ab viewpoints-debate --model-b gemini-3.7-flash`）

每臂兩跑、7 個 canary 日、28 次呼叫，零 degrade 零 schema 失敗。

| | 3.5-flash（兩跑平均） | 3.7-flash（兩跑平均） |
|---|---|---|
| input token | 78,179 | 78,113（−0.1%） |
| output token | 3,708 | **3,833（+3.4%）** |
| latency mean / p95 | 8.2s / 10–13s | 8.9–9.5s / 11–27s |

★ **這一輪第一次跑出來的 `costUsd` 是假的**：`pricing.ts` 當時沒有 3.7 的 entry，
`priceFor` 靜靜回 `FALLBACK_PRICING`，而那個 fallback 剛好等於 3.5-flash 的價，
於是 `model:ab` 的 impliedPrice 反推回報「兩臂同價」。照著讀會得到「沒得省」的反向結論。
補上 entry 後用同一批 token 重算才是下面的數字。（B1 那筆 `warns=1` 也是這個
pricing 警告，不是品質降級。）

## 量測二：品質（`brief:quality` pairwise，每次呼叫內建兩個 orientation）

| 組別 | 非 tie / 21 個判定 |
|---|---|
| 同臂 A（3.5-flash 自己兩次）＝**雜訊底線** | **6（28.6%）** |
| 同臂 B（3.7-flash 自己兩次） | 2（9.5%） |
| 跨臂 A1 vs B1 | 5（23.8%）｜3.5 勝 3、3.7 勝 2 |
| 跨臂 交換位置 | 4｜3.5 勝 2、3.7 勝 2 |

**跨臂非 tie 率低於同臂雜訊底線、勝負合計 5–4 ＝ 差異落在雜訊裡。**

第二個證據：同一組比較跑兩次（A1-vs-B1 與交換位置）**互相矛盾**——07-21 一次判 3.5 勝
深度＋可讀、另一次全 tie；07-23 一次判 3.7 勝可讀、另一次判 3.5 勝深度。既然
`quality-judge.ts` 每次呼叫內部已經跑兩個 orientation 去位置偏誤，這個矛盾就是 judge
自己的 run-to-run 不可重現：在這個效果量下量尺解析度不夠。

★ 因此**「交換位置」那 7 次是多跑的**（約 $0.28）。位置偏誤在工具裡就控制掉了，
下次不必再跑一遍——但它意外變成儀器的一致性檢查，值得記一筆。

## 錢的絕對值（prod 14 天實測 token 外推）

六個 agent 的 prod 用量：input 1,745,803 / output 296,176（14 天，來自
`background_jobs.metadata.llmCalls`）。帶入 A/B 量到的 output +3.4%：

| | 年化 | vs 現況 |
|---|---|---|
| `gemini-3.5-flash` | $137.8 | — |
| 3.7 折扣期 | $64.1 | **−53%** |
| 3.7 折扣後（2027-01-01 起） | $128.2 | −7% |

**折扣只剩 130 天，今年實際省下約 $26，之後每年約 $10。**

★ 這條 pipeline 全年的 LLM 帳大約 $155（含 narrative-writer 的 3.1-pro 約 $17）。
真正的量在 corpus 那條（entity-summary 一天 432 calls），而它 2026-08-02 就換到
flash-lite 了——$500/yr 的那一刀已經砍過。這裡的天花板就是幾十塊，
**不要拿「省了一半」當成省了很多**。

## 沒有量到的

- **六個裡只有 `viewpoints-debate` 實測過。** 另外五個靠的是可逆性不是證據
  （`AGENT_MODELS` env 一行可退、不必部署）。
- **`analyst-tier1` 佔這六個成本的一半**，產結構化 claim 接 grounding 與合規，
  而 `model:ab` 沒有它的 target。要真的驗它得先寫一個——以 $26 的獎品來說不划算，
  這是刻意的取捨，不是忘了。崩潰型失敗有 `CLAIMS-ZERO` / `CLAIMS-UNGROUNDED`
  接著（#295），微幅退化沒有偵測手段。
- **canary fixture 七天裡只有 08-12 / 08-13 帶 claimLedger**，其餘五天的 input 比 prod 短，
  所以 A/B 的成本比例可信、絕對值偏低。
